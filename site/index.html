a fresh startthe idea

The systems we rely on carry decades of code that nobody would write the same way today. SlateOS starts over: a kernel, a shell, a desktop and a filesystem made new, in a memory-safe language, with nothing preinstalled that hasn't earned its place. It speaks Linux fluently, so everything you depend on comes with you.

Every addition must justify itself.
the systemclean room

Meets Linux at its interfaces. Never at its code.

The Slate kernel answers the same system calls Linux does, written from public documentation and checked against how real Linux behaves. Distro binaries, container images and desktop apps run unchanged, on a kernel that shares no lineage with the one they were built for.

allowed

  • Manual pages
  • Public specifications
  • Hardware makers' documents
  • Observed behaviour, tested

never

  • Linux code
  • BSD code
  • Any UNIX code
  • Translations of them
  • Your softwareFirefox, Podman, git, GCC, Python. Unmodified Linux binaries.
  • Linux personalityx86-64 system calls, /proc, ELF, namespaces, cgroup v2, seccomp.
  • Native interfaceslate-rt and slate-libc, Slate's own calls.
  • Slate kernelRust, monolithic, multi-core. Its own memory, scheduler, VFS and TCP/IP.
  • Your hardwarex86-64 PCs. NVMe, SATA, USB, wired Ethernet, AMD graphics.
securityslate mode

Two domains. One quiet system.

By default SlateOS runs in Slate mode, which goes further than Unix ever did. Linux programs run beside it in a domain of their own, with exactly the behaviour they expect, and they can't reach past its walls.

An image nobody can scribble onThe system is immutable and signed. Not even root can change it; only the updater can.
No all-powerful rootA privilege broker asks you, in a dialog no app can imitate. No set-user-ID programs.
Signed code, strict W^XA native program is trusted only if its signature checks out. Memory is writable or executable, never both.
Linux, one switch awayTurn on compatibility and Linux programs run in their own domain. They can't see or signal Slate's processes.

themesfour of them

One desktop, four moods.

Graphite, Light, Copper Noir and Sediment, chosen in Settings › Appearance. Every window, app and menu follows the theme, and each one comes with wallpapers drawn to match. These are real renders, not mock-ups.

The default: warm graphite, chalk for whatever has your attention, and colour only where it means something.

dark · the default
graphicsits own driver

Its own pixels, on your screen.

SlateOS drives the display with its own code. Every graphics card works out of the box, and on supported AMD Radeon graphics there is more: SlateOS's own AMD display driver, with your monitor at its own resolution and windows composited on the GPU.

the default

SlateOS only

Any card, on the framebuffer the firmware sets up, with the boot loader picking the display's native mode. Strata composites on the processor, and a 4K desktop stays smooth.

amd radeon · opt-in

Full graphics

On supported integrated Radeon graphics (tested on Ryzen 7000-series "Raphael"): copies on the GPU's copy engine, blending on SlateOS's own shaders, and a hardware pointer.

off by defaultFull graphics loads AMD's firmware, software from AMD that runs on the card itself. You choose it in the installer or in Settings › Displays.
always a way backThe first start asks "Keep full graphics?" and goes back by itself after 20 seconds. The boot menu keeps a "standard graphics" entry.
4k on the cpuWithout GPU help, the launcher, a window drag and a workspace switch all stay inside a 60 Hz frame at 3840 × 2160.

updatesslatefs

Updates you can take back.

SlateFS is Slate's own copy-on-write filesystem. An update is written beside the running system, never over it. The next boot is a trial: if it fails, the kernel starts the last good system by itself, and every earlier one waits in the boot menu.

copy-on-writeNothing is overwritten in place, so a power cut can't leave a half-written system.
checksumsEvery block is checked when it's read.
encryptedThe root partition is encrypted by default and unlocked at boot.
ext4 tooYour existing Linux drives open, read and write.

installthe installer

Moves in beside you.

Start it from a USB stick and try the desktop from memory before you change a thing. When you install, SlateOS can take the free space next to the system you have, and both will be in the boot menu.

Try it first. The live desktop runs from RAM, as a guest.
Beside, erase, or your own partitions. The table is written last, so a failed install changes nothing.
Encrypted by default. Your root partition is locked with your password.
Your keyboard, your time. Sixteen layouts with dead keys, and your time zone.
Full graphics, if you want it. On supported AMD Radeon graphics, the Desktop step asks.
Larger text, high contrast. One button away on the welcome screen. A text installer is in the boot menu.

hardwarewhat it runs on

Its own drivers. Honest about them.

Every driver is written for SlateOS, so it works with some hardware and not yet with the rest. Check your PC first: a 64-bit Intel or AMD machine, in UEFI or legacy BIOS mode, with Secure Boot off.

works today

disks
NVMe, SATA (in AHCI mode) and USB drives
wired network
Intel I210, I211 and 82576 cards, and standard USB Ethernet adapters
graphics
Any card, on the firmware's framebuffer. Full graphics on supported AMD Radeon integrated graphics
input
USB keyboards and mice (on the USB 3 controller) and PS/2
bluetooth
USB adapters pair with devices

not yet

  • Wi-Fi · use a cable or a USB Ethernet adapter
  • Sound
  • Sleep · the power button shuts down cleanly
  • Bluetooth keyboards, mice and headphones
  • Many built-in Realtek network ports
  • Secure Boot · the bootloader isn't signed

The full table, and what to do when something goes wrong, are in the install guide. It also runs in QEMU, virt-manager and GNOME Boxes.

get itfrom source

Begin again.

SlateOS is young and in active development, with laptop support next. There are no downloads yet: make builds the install media from source, a USB image and an ISO.

git clone https://github.com/neuralpunk/slate-os
  1. On Linux, with rustup, git, a C compiler and binutils: cd slate-os && make
  2. Write target/slate-usb.img to a USB stick, byte for byte, with dd or GNOME Disks.
  3. Start the PC from the stick, try the desktop, then install. Or make run boots it in QEMU.

alpha SlateOS is alpha software. Don't use it in production. Expect bugs, crashes, missing features and data loss, and changes between releases that break what worked before.

The first build fetches the pinned Rust toolchain and takes a few minutes. Installing erases the disk you choose unless you install beside what is on it: back up first.
